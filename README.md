# codecrafthub
CodeCraftHub
CodeCraftHub is a beginner-friendly REST API for managing courses. It allows users to create, view, update, and delete courses using standard HTTP methods.

The project is built with Python and Flask. Course information is stored in a local
courses.json
file, making the project easy to understand without requiring a database.

This project is useful for learning:

REST API concepts
HTTP methods
JSON requests and responses
CRUD operations
Flask routes
API testing with
curl
Error handling
Working with a JSON data file

Project Overview
CodeCraftHub provides an API for managing courses.

Each course contains information such as:

API Documentation
The base URL for local development is:

http://127.0.0.1:5000
All examples below use this URL.

Course data format
A course uses the following JSON fields:

Field	Type	Required	Description
id
Integer	No	Unique course identifier generated by the API
name
String	Yes	Name of the course
description
String	Yes	Description of the course
target_date
String	Yes	Target date in
YYYY-MM-DD
format
status
String	Yes	Course progress status
Valid status values are:

Not Started
In Progress
Completed
Example:

{
  "name": "Python Programming",
  "description": "Learn Python programming and Flask.",
  "target_date": "2026-12-31",
  "status": "Not Started"
}
Endpoints
GET
/api/courses
Returns all courses.

Request
curl -i http://127.0.0.1:5000/api/courses
Successful response
HTTP/1.1 200 OK
Content-Type: application/json
Example response:

[
  {
    "id": 1,
    "name": "Python Programming",
    "description": "Learn Python programming and Flask.",
    "target_date": "2026-12-31",
    "status": "Not Started"
  }
]
If no courses exist, the response may be:

[]
POST
/api/courses
Creates a new course.

Request
curl -i -X POST http://127.0.0.1:5000/api/courses \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Python Programming",
    "description": "Learn Python programming and Flask.",
    "target_date": "2026-12-31",
    "status": "Not Started"
  }'
Successful response
The expected status is:

HTTP/1.1 201 CREATED
Content-Type: application/json
Example response:

{
  "message": "Course created successfully.",
  "course": {
    "id": 1,
    "name": "Python Programming",
    "description": "Learn Python programming and Flask.",
    "target_date": "2026-12-31",
    "status": "Not Started"
  }
}
The API may assign a different ID depending on the existing data.

GET
/api/courses/<id>
Returns one course by its ID.

Request
curl -i http://127.0.0.1:5000/api/courses/1
Replace
1
with the ID of the course you want to view.

Successful response
HTTP/1.1 200 OK
Content-Type: application/json
Example:

{
  "id": 1,
  "name": "Python Programming",
  "description": "Learn Python programming and Flask.",
  "target_date": "2026-12-31",
  "status": "Not Started"
}
PUT
/api/courses/<id>
Updates an existing course.

This example updates course
1
.

Request
curl -i -X PUT http://127.0.0.1:5000/api/courses/1 \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Advanced Python Programming",
    "description": "Learn Python, Flask, and REST APIs.",
    "target_date": "2027-01-15",
    "status": "In Progress"
  }'
Successful response
HTTP/1.1 200 OK
Content-Type: application/json
Example:

{
  "message": "Course updated successfully.",
  "course": {
    "id": 1,
    "name": "Advanced Python Programming",
    "description": "Learn Python, Flask, and REST APIs.",
    "target_date": "2027-01-15",
    "status": "In Progress"
  }
}
When using
PUT
, provide all required course fields unless the application specifically supports partial updates.

DELETE
/api/courses/<id>
Deletes an existing course.

Request
curl -i -X DELETE http://127.0.0.1:5000/api/courses/1
Successful response
A typical response is:

HTTP/1.1 200 OK
Content-Type: application/json
{
  "message": "Course deleted successfully."
}
Some implementations return:

HTTP/1.1 204 NO CONTENT
A
204
response does not contain a response body.

Complete CRUD Example
The following commands demonstrate a complete create, read, update, and delete workflow.

1. Create a course
curl -i -X POST http://127.0.0.1:5000/api/courses \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Web Development",
    "description": "Learn HTML, CSS, JavaScript, and Flask.",
    "target_date": "2026-11-30",
    "status": "Not Started"
  }'
Look at the response and note the course ID.

2. View all courses
curl -i http://127.0.0.1:5000/api/courses
3. View one course
Replace
1
with the ID returned when the course was created:

curl -i http://127.0.0.1:5000/api/courses/1
4. Update the course
curl -i -X PUT http://127.0.0.1:5000/api/courses/1 \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Web Development - Updated",
    "description": "Learn REST API development with Flask.",
    "target_date": "2026-12-15",
    "status": "In Progress"
  }'
5. Delete the course
curl -i -X DELETE http://127.0.0.1:5000/api/courses/1
Error Responses
The API should return a suitable HTTP status code and a JSON error message when a request fails.

Missing required field
This request is missing
name
:

curl -i -X POST http://127.0.0.1:5000/api/courses \
  -H "Content-Type: application/json" \
  -d '{
    "description": "This course does not have a name.",
    "target_date": "2026-12-31",
    "status": "Not Started"
  }'
Expected response:

HTTP/1.1 400 BAD REQUEST
Example body:

{
  "error": "Missing required field: name"

    "status": "Not Started"
  }'
Expected response:

HTTP/1.1 400 BAD REQUEST

  -d '{
    "name": "Python Programming",
    "description": "Learn Python programming.",
    "status": "Not Started"

Expected response:

HTTP/1.1 400 BAD REQUEST

    "name": "Python Programming",
    "description": "Learn Python programming.",

Expected response:

HTTP/1.1 400 BAD REQUEST

{
  "error": "Invalid status"

Invalid date format
curl -i -X POST http://127.0.0.1:5000/api/courses \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Python Programming",
    "description": "Learn Python programming.",
    "target_date": "December 31st",
    "status": "Not Started"
  }'
Expected response:

HTTP/1.1 400 BAD REQUEST
Dates should use this format:

YYYY-MM-DD
Example:

2026-12-31
Invalid JSON
curl -i -X POST http://127.0.0.1:5000/api/courses \
  -H "Content-Type: application/json" \
  -d '{"name": "Python Programming",'
Expected response:

HTTP/1.1 400 BAD REQUEST
Course not found
Request a course ID that does not exist:

curl -i http://127.0.0.1:5000/api/courses/99999
Expected response:

HTTP/1.1 404 NOT FOUND
Example body:

{
  "error": "Course not found"
}
The same type of response should be returned when updating or deleting a course that does not exist:

curl -i -X PUT http://127.0.0.1:5000/api/courses/99999 \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Updated Course",
    "description": "This course does not exist.",
    "target_date": "2026-12-31",
    "status": "In Progress"
  }'
curl -i -X DELETE http://127.0.0.1:5000/api/courses/99999

Install Flask:

pip install Flask
Alternatively, run the application directly:

python app.py
Python command is not found
Try:

python3 --version
If that works, use
python3
instead of
python
:

python3 app.py
Address already in use
If you see an error similar to:

Address already in use
Port 5000 is in use
Another application is already using port
5000
.

You can either stop the other process or change the port in
app.py

app.run(
    host="0.0.0.0",
    port=5001,
    debug=True
)
Then use:

curl -i http://127.0.0.1:5001/api/courses
Connection refused
If
curl
returns:

Connection refused
Make sure the Flask server is running:

python app.py
Also verify that you are using the correct port:

curl -i http://127.0.0.1:5000/api/courses
The API returns
302
in GitHub Codespaces
If the public Codespaces URL returns:

HTTP/2 302
and redirects to:

https://github.dev/pf-signin

Test the API locally instead:

curl -i http://127.0.0.1:5000/api/courses

Incorrect environment variable usage
Set the base URL:

export BASE_URL="http://127.0.0.1:5000"
Use
$BASE_URL
when making requests:

curl -i "$BASE_URL/api/courses"
Do not write:

curl -i "BASE_URL/api/courses"
The
$

[]
Invalid JSON response
Check that:

The Flask application is running
The endpoint URL is correct
The request includes the correct
Content-Type

The request body uses valid JSON

{

REST API Concepts
What is REST?
REST is a common approach for building web APIs. A REST API uses URLs to represent resources and HTTP methods to describe actions.

In CodeCraftHub, the resource is a course.

/api/courses
represents the collection of courses.

/api/courses/1
represents one specific course.

HTTP methods
Method	Meaning	Example
GET
Read data	Get all courses
POST
Create data	Create a course
PUT
Update data	Update a course
DELETE
Delete data	Delete a course
HTTP status codes
Status	Meaning
200 OK
Request succeeded
201 CREATED
A new resource was created
204 NO CONTENT
Request succeeded without a response body
400 BAD REQUEST
The request contains invalid data
404 NOT FOUND
The requested course does not exist
500 INTERNAL SERVER ERROR
An unexpected server error occurred
Request headers
When sending JSON data, include this header:

Content-Type: application/json
In
curl
:

-H "Content-Type: application/json"
This tells the server that the request body contains JSON.

Request body
The request body contains the data being sent to the API.

Example:

{
  "name": "Flask REST APIs",
  "description": "Build REST APIs using Flask.",
  "target_date": "2026-12-31",
  "status": "Not Started"
}
